Funksjoner og versjonshistorikk

«ca.» = usikkert versjonsnummer. Forkastede forsøk er tatt med fordi de viser hvorfor dagens arkitektur ser ut som den gjør. Tabellen er kronologisk; nåværende versjon er 3.22.1.

v3.10.0 (Unlist + umiddelbar gjenoppbygging) var en FEIL retning. Den ble trodd løst fordi testen brukte formler i samme arbeidsbok og samme syklus. Den ble senere erstattet av UPSERT i v3.20.0+ (rotårsak: Unlist fryser strukturerte kryss-ARK-referanser til statiske områder). Ikke gjeninnfør Unlist/Resize/rebuild. Se designbeslutning 1.

Opprinnelig idénotat (11.09.2026): hva som stemmer og hva som er foreldet

Idénotatet «Nettskjema API v3 – Excel/VBA integrasjon» (18 630 B) var utgangspunktet for v1.0.0 og er delvis foreldet.

Stemmer fortsatt:

  • Token-URL https://authorization.nettskjema.no/oauth2/token (korrigerte den opprinnelige spesifikasjonen som oppga https://nettskjema.no); API-basis https://nettskjema.no/api/v3; Basic Auth med clientId:clientSecret, body grant_type=client_credentials.
  • Token caches i minnet, 60 s sikkerhetsmargin, fornyes ved 401 (én gang, ingen uendelig løkke). 429: Retry-After, ellers eksponentiell backoff 2/4/8/16 s, tak 30 s, MAX_RETRIES 5. 5xx: retry med backoff. 400/403/404: ingen blind retry, vis detaljert feilmelding (feil form-ID, manglende tilgang).
  • WinHTTP (WinHttp.WinHttpRequest.5.1) med eksplisitte timeouts; MSXML for Base64; VBA-JSON (github.com/VBA-tools/VBA-JSON) som parser; ikke hardkode felt (les dynamisk); 2D-array-skriving i stedet for celle-for-celle; ListObject; Log-ark med tidspunkt/operasjon/form/HTTP-status/forsøk/resultat/feilmelding/antall rader/varighet; testplan med 12 punkter (gyldig/feil secret, ugyldig formId, manglende tilgang → 403, 401 → nytt token + ett retry, 429, 500, tomt resultat, checkbox, null → tom celle, mange svar).
  • UPSERT på submission-id som mest robuste modus (ble senere bygd i v3.20.0). Client-identiteten [clientId]@apiclient er til tilgangsstyring, ikke til Basic Auth. Personvern: respondentdata er sensitiv; vurder om identifikatorer må importeres.
  • Referanser notatet nevnte: UiO survey-api-schemas (github.com/unioslo/survey-api-schemas, Submission.json versjon 2024-09, version_minor 2; metadata created, answer_time, submission_id) og nettskjema-mcp (github.com/orjahren/nettskjema-mcp). Submission-schemaet er ikke det /answers returnerer; /answers-formatet ble avdekket empirisk.

Foreldet eller feil:

  • GET /api/v3/form/{formId}/submissions som primært endepunkt (finnes ikke i v3; brukes /answers med x-ndjson). Antagelsen om Accept: application/json og «bredt» JSON-format per submission (answers/metadata-objekter, checkbox som boolske underfelter) stemmer ikke for /answers, som er langt NDJSON.
  • «Test connection» via /api/v3/me (bruk /form/me).
  • Anbefalt struktur Dashboard/Settings/Data/Log med ett Form ID og Client ID i Settings-ark (erstattet av multi-tilkobling, ett ark per skjema, skjult register).
  • «Aldri lagre client secret i arbeidsboken» / Credential Manager som anbefalt lagring: reversert i v3.20.0 (secret i skjult ark, Credential Manager kun fallback).
  • Eksempelkode med TimeSerial for utløp (gir Overflow) og .ResponseText (mojibake). «CSV bør vurderes seriøst» ble ikke fulgt (csv-report er octet-stream, ikke brukt). Inkrementell import («hent bare nye») ble ikke bygd; full henting + UPSERT brukes. Foreslått User-Agent «Excel-Nettskjema-VBA/1.0»: kildene sier ikke om den er implementert.
  • Idénotatets timeoutverdier (10000/10000/30000/120000) tilsvarer i dag data-GET-verdiene.
